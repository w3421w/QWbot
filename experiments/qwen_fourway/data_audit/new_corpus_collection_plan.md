# QWbot 新增语料规划

本文件是采集前规划，不下载、不联网爬取、不开始训练。数量是“通过授权、匿名化、人工审核后”的目标有效样本量，不是原始下载量。

## 1. 最值得新增的五类

|优先级|语料类|建议有效样本量|收集形态|主要用途|
|---:|---|---:|---|---|
|1|经授权的 QQ 多人群聊|12,000 个多轮对话片段，约 60,000 消息；至少 1/3 含三人以上、1/4 含跨轮指代|保留时间窗、说话人匿名 ID、回复/引用关系和必要的前后文|**SFT 主力**：群聊接话、指代、昵称、回旋镖、转折；少量稳定事实另建检索库|
|2|B 站评论区/弹幕/视频简介（取得授权）|8,000 个问答或评论串；不同分区至少各 1,000|按视频/评论串保留上下文，去除只靠画面才能理解的样本或补充文字描述|评论风格和互动 **SFT**；UP 主信息、作品资料、时间敏感事实进检索库|
|3|NBA + 足球|各 5,000 个高质量讨论样本，共 10,000|赛前/赛后、战术、球员表现、规则和球迷争论分层；保留日期与赛事标识|观点表达、比较、解释 **SFT**；赛程、阵容、统计、历史记录进检索库|
|4|CS2 + Valorant + DOTA2|每个 3,000 个，共 9,000|按游戏、模式、段位、版本、赛事分层；拒绝只有游戏名的梗|策略/复盘/队友沟通 **SFT**；版本、英雄/枪械数值、赛事结果进检索库|
|5|日常生活 + 动漫影视 + 科技数码|每类 4,000 个，共 12,000|真实问题、澄清、情绪和经验；动漫影视需作品上下文，科技需版本/型号/日期|日常回应和解释 **SFT**；作品/产品规格及易变信息进检索库|

按上表先按“对话/问答片段”计，合计约 43,000 个片段；QQ 部分另要求约 60,000 条消息以保证多轮上下文，其他来源的消息数不在本表虚构换算。若人工通过率低于 50%，先补质量再补数量，不用低质短梗填数。

## 2. QQ 群聊的匿名化与授权门槛

在拿到任何群聊文件前，必须同时满足：

1. **逐群授权**：群主/管理员和实际发言者的可追溯授权记录；明确允许机器学习训练、内部评测、保存期限、撤回渠道和再分发范围。仅“群文件可下载”或单个成员口头同意不够。
2. **默认不收集私人内容**：身份证、手机号、邮箱、地址、支付信息、账号、二维码、私聊、未成年人信息、医疗/法律个案、内部工作资料直接剔除；必要时整段删除，而不是只打码。
3. **稳定匿名化**：用户映射为随机 `U0001` 等；昵称、群名、链接、图片文件名、@提示、引用中的原昵称全部一致替换；原始映射表与训练集分离并加密，审计结束销毁。
4. **上下文最小化**：只保留回答所需的前后文和时间窗；图片、语音、文件没有文字转录或授权时不入库；不能靠图片猜测内容。
5. **撤回和审计**：保存来源群、授权版本、采集时间、脱敏规则、删除请求日志；收到撤回后能按 `conversation_id` 和 `message_id` 全链路删除。
6. **人工复核**：先做 PII/敏感内容扫描，再由两名审核者确认语境可恢复、回复对象明确、没有把玩笑当事实；审核样本不得直接暴露原昵称。

## 3. 外部语料的版权、许可和条款核查

- 对 `zh_meme_sft_8k`：在使用前核对数据集页面的许可证、原始文本的上游授权、是否允许商业使用/模型训练/再分发、归属和衍生作品条款。当前 manifest 只有来源 URL、哈希和切分说明，不能代替许可证证明；7,377 条候选全为 `unreviewed`。
- 对 B 站、论坛、赛事站和社交平台：保存抓取时适用的服务条款、API/导出许可、机器人规则、版权声明和地域限制；网页公开不等于可用于训练。
- 对包含用户生成内容、图片、字幕、直播转录的语料：分别核查文字、音视频、图片、商标和个人信息权利；没有明确许可就只做检索索引或不使用，不进 SFT。
- 保存每个来源的 `source_url`、访问/导出日期、许可证原文快照、版本号、SHA-256 和允许用途；许可证不清晰的文件隔离，不与已授权数据混合。
- “知识库”也不是版权豁免。检索库只保留必要摘录、来源链接和更新时间，输出时遵守来源的引用、缓存和删除要求。

## 4. SFT 与检索知识库的分工

**适合 SFT**：经授权且已匿名化的多轮互动；稳定的回应结构、澄清、礼貌/玩笑边界、观点表达、游戏复盘方法。样本要保留问题—回应关系，不能把整页评论平铺成 completion。

**更适合检索库**：赛程、比分、球员/选手当前队伍、版本号、英雄/枪械数值、产品规格、法律政策、医疗指南、作品发行信息。此类内容随时间变化，训练会固化过时答案；入库时带日期、版本和来源。

**不应直接用于 SFT**：未授权原始群聊、仅有图片而无描述、无法恢复回复对象的短句、重复刷屏、个人隐私、未经核验的事实断言和整段外部网页复制。

## 5. 下一阶段原始文件处理顺序

1. 冻结并只读保存 `datasets/kangba_raw/data/tieba_post_detail_page_1~106/*.json`，建立帖子 ID、回复 ID、页码、时间和原始哈希索引；不要继续从派生 CSV 回推“原始”。
2. 对抗吧原始回复按“楼层/引用可恢复性、是否回答楼主、重复、广告、隐私、事实风险”做分层人工抽样；先处理 911 条楼主正文为空和 107,578 条恢复候选中的高频重复。
3. 逐条复核 `datasets/kangba_v44_metadata.csv` 中 298 条 `source_split=new` 原创示范，并与真实贴吧样本分开统计；不要把原创示范计为新外部覆盖。
4. 审核 `zh_meme_sft_8k_review_candidates_20261009.csv` 前，先完成许可证和上游权利核查；继续保持其 `test.jsonl`、`validation.jsonl` 与训练隔离。
5. 为 31 题测试集建立冻结清单和近重复审查表，检查原帖组、同义改写和模板化原创示范；测试题及其上下文永不进入 SFT。
6. 在以上完成后，才按本计划顺序接收 QQ、B 站和体育/电竞新源；每个来源单独目录、单独许可证记录、单独 train/valid/test 分组。

## 6. 采集后的最低验收指标

- 每类至少 90% 样本有可恢复上下文，且能指出回答对象；
- 每类至少 70% 样本由人工确认存在真实问答/讨论关系；
- 训练/验证按原帖、视频、群组或对话组隔离，不能随机打散同一串对话；
- 近重复、PII、未授权和无法核验事实分别有拒绝原因；
- 报告同时列出全量计数和抽样估计，禁止用抽样比例冒充全量覆盖。
